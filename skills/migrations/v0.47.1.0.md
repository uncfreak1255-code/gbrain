# v0.47.1.0 - Source hygiene recovery

GBrain now protects database-only pages before source cleanup and refuses new
work against an archived source.

## What the orchestrator does automatically

`gbrain upgrade` runs `gbrain apply-migrations --yes`, which applies:

1. **Migration 124** - rejects writes that reference an archived source.
2. **Migration 125** - guards source-bearing minion jobs.
3. **Migration 126** - permits only safe cancellation or terminalization of a
   job after its source is archived.
4. **Migration 127** - blocks progress, lock renewal, and other job continuation
   after archival.
5. **Migration 128** - guards every update to a source-owned row, even when the
   update does not change `source_id`.
6. **Migration 129** - keeps unresolved legacy source identifiers writable while
   retaining row locks and write protection for known archived sources.
7. **Migration 130** - adds a transaction lock shared by every guarded writer
   and taken exclusively by archive, closing the race before a source row exists.
8. **Migration 131** - rechecks the old source owner on updates so rows cannot
   be moved out of an archived source to escape the write guard; scalar
   references may still be cleared for cleanup.
9. **Migration 132** - extends the guard to child rows that inherit ownership
   through `pages(id)` and to path-routed sync jobs, using statement-level
   checks that avoid serializing vector columns.
10. **Migration 133** - adds per-source archive drain markers and durable,
    exact provider lease rows. Provider calls run outside database transactions;
    archive blocks new submissions, waits for existing tokens, and resumes an
    interrupted drain with the same source generation.
11. **Migration 134** - applies the source lifecycle guard to per-source and
    legacy global cycle locks.
12. **Migration 135** - keeps a pure OAuth client revocation available after
    source archive while rejecting any piggybacked client or binding change.

The migrations are idempotent and update existing brains without deleting pages.
Each intermediate guard migration also keeps unresolved legacy source identifiers
writable, so an older writer does not hit a temporary missing-source error while
the upgrade advances one migration at a time. Those writers take the shared
lifecycle lock from the first guard migration, and known archived sources remain
blocked throughout.

If Doctor or Advisor reports `archive_resume`, the committed drain is safe but
unfinished. Resume the exact source instead of clearing database rows by hand:

```bash
gbrain sources archive <source-id>
```

For a shared Postgres brain, a worker crash can leave a durable provider lease
whose owner cannot be proven dead automatically. After reviewing the owner and
waiting at least ten minutes since its last heartbeat, use the explicit recovery:

```bash
gbrain sources archive <source-id> --revoke-stale-leases --confirm-destructive
```

This deletes only stale leases from source epochs fenced by the current drain.
Any late provider output from a revoked lease is discarded. Fresh leases and
malformed future-epoch rows remain, so archive keeps waiting rather than guessing.

## Verify the outcome

```bash
gbrain apply-migrations --yes
gbrain doctor --json
gbrain sources list --json
```

Doctor should report the source-path, sync-freshness, source-routing, and
multi-source-drift checks without a stale archived-source warning.

If a source still needs recovery, export it before changing its routing:

```bash
gbrain export --source <source-id> --dir ./gbrain-source-recovery
```

Keep the generated manifest with the recovered pages. Do not archive a populated
source merely because its checkout is missing.

## If something goes wrong

Run `gbrain doctor --json` and inspect `~/.gbrain/upgrade-errors.jsonl` if it
exists. File an issue at https://github.com/garrytan/gbrain/issues with those
outputs and the migration number that failed. Do not include exported private
page contents in a public issue.
