## Recall source selection

`recall.source_id` narrows both fact and page arms using the existing authorized
scope resolver, then checks source liveness. Explicit `default` is not omission.
With no selector, fact scope and page federation retain their previous behavior.
The opted-in thin CLI uses engine-free scope resolution and refuses `--brain`;
its source tests execute the real remote dispatcher, not only a canned response.
Degraded serving has its own explicit `serve` dispatch guard, so the generated
registry cannot assign its flags to the preceding thin-recall branch.
`test/cli-recall-flag-ownership.test.ts` pins fresh generation and real CLI
rejection of serve-only flags before a brain opens.

## Files

- `src/core/facts/question-recall.ts` — recall's `question`: `parseQuestionParam` refuses `supersessions`, `include_expired` and more than 2,000 characters with the corrected call as `fix.mcp`; `rankFactsByQuestion` resolves `entity` per source to pairs and runs `unlinkedNamesakes` on the whole filtered pool before ranking, embeds the question once through `embedQueryBounded` (the gateway's query-embedding cache, so a `query` of the same text shares it; the embedding opt-out, a missing provider or a failed embed rank by term share and set `facts_degraded.reason`), ranks with `search/fact-relevance.ts` under the `recall.question_admission` rule (`reserve` default, or `facts_arm`; pool, uncomparable count and rule read concurrently), hydrates the ranked ids through `rowToFact`, counts uncomparable facts (`facts_degraded.unembedded`, the `facts_unembedded` notice with the `embed --stale --facts` preview), sets `calibration` (recall's informational `facts_calibration: {status: 'unmeasured', model_key}`, #6590) when the cosine arm ran on a model with no row in `FACT_ADMISSION_FLOOR_EVIDENCE` (`search/fact-relevance.ts`, shared with doctor `fact_admission_floors`), with the `facts_calibration_unmeasured` info notice deduped per brain per session by its `dedupe_key` (test `test/recall-facts-calibration-6590.test.ts`), and turns a DB error into `unavailable` (`fix.next: wait`). `recallHintNotice` builds `recall_hint`. Tests: `test/recall-question.test.ts` (both engines), `test/recall-question-cli.test.ts`.
- `src/core/ops/facts-scan.ts` — opt-in `recall` scan v1 validates an absolute creation-time cutoff and safe-integer cursors, requires one live authorized source, and returns a fixed upper ID with explicit `has_more`. Its engine read includes expired facts on request while applying current privacy and read-eligibility policy before paging. A full replay is required for late commits with lower IDs; the bound is not a commit watermark. `test/facts-keyset-scan.test.ts` and `test/facts-keyset-scan-cli.test.ts` pin the behavior.

- `src/core/ops/facts.ts` — shared fact/memory operations, including `recall` and the `delta` cursor. Every recall response carries `facts_order` (`newest`, or `relevance` when `question` ranked the facts arm through `facts/question-recall.ts`); a `query` call without `question` or a fact filter emits `recall_hint`. `context_pack` and `delta` `facts[]` carry recall's `fact_id` and `provenance` (the stored `facts.source`), read in one batched `withProvenance` lookup by the delivered ids, so hot memory and MCP `_meta` stay unchanged; remote callers get provenance through the same redaction as the fact text, and it never enters `text` (#6146, `test/context-pack-fact-traceability.test.ts`). `context_pack` `entity_facts[]` carry the packed cards' own facts (#6724, entry in core-services-3.md). Recall keeps source/visibility and fact filters before per-arm candidate limits. Its default/explicit `facts_first` packing preserves the frozen memory-verb contract, including the positive sub-one budget quirk. Optional `query_first` packs the ranked page prefix first only with a nonblank query and positive finite budget; floor-zero and exhausted remainders explicitly return empty arms rather than call the unbounded zero-budget packer. Neither arm skips oversized prefix items or truncates. No-query and inactive-budget paths keep legacy behavior. Only policy-supplied calls add `budget_packing` effective-policy/reason and candidate/kept/dropped/estimated-used accounting. Counter sums match the frozen fields. Do not change the global packer or fact relevance to implement this policy. Delta rejects calendar-invalid ISO dates and years outside 0001-9999 (on the parsed UTC value) before normalization across fractional-second forms, while preserving valid six-digit microsecond cursors. Delta's per-arm cursor (contributor audit wave P0): the start position resolves `cursor` > `since` (whole tuple, slug only when supplied) > the session row; each arm advances through its delivered prefix only (`src/core/context/delta-cursor.ts`), an arm that failed or never finished holds, the conservative legacy `next_cursor.since`/`slug` never passes the oldest undelivered fact, and a legacy caller at an unpageable same-timestamp boundary is refused with `delta_cursor_upgrade_required`. Incomplete wakes emit `delta_incomplete` (`fix.next: wait`, `report` on the third consecutive wake, counted atomically in `session_context_state.degraded_wakes` with an in-process fallback when the store is down); a failed state read refuses with `unavailable`/`session_state` instead of re-initializing at now. `test/recall-budget-policy.test.ts` pins recall behavior; `test/ambient-recall.test.ts` pins delta cursor validation; `test/delta-cursor-integrity.test.ts` (both engines) pins every no-advance path, the facts drain, legacy safety and the commit-visibility bound.
